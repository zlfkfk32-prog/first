# 한국투자캐피탈 공개정보 카드레터

부동산 PF·부동산 금융을 우선으로, **캐피탈업권**, **개인·리테일 금융**과 **시공능력평가 TOP100 시공사**
전용 칸을 갖춘 A4 한 장 PDF 생성기입니다. 매일 오전 8시 **한국시간(Asia/Seoul)**
실행용 GitHub Actions 파일을 제공합니다. 회사 공식 발행물이 아닌 검토용 프로토타입입니다.
회사 내부 자료·고객/거래 개인정보 입력 기능이나 메일 발송 기능은 없습니다.

## 카드 구성

한 페이지에 고정된 4개 칸을 유지합니다. 조건에 맞는 기사가 없으면 다른 분야로 채우지 않고 상태를 표시합니다.

| 칸 | 기사 한도 | 선별 기준 |
|---|---:|---|
| 부동산 PF·정책 | 2건 | PF·담보·조달·부동산 시장 / 관련 공식기관 정책 우선 |
| 캐피탈업권 | 1건 | 국내 캐피탈사·업권의 실적, 조달, 연체, 경영, 인수금융 등 |
| 개인·리테일 금융 | 1건 | 개인·가계·주담대·전세대출, 자동차금융·리스·할부, 금융소비자 보호 |
| TOP100 시공사 주요 뉴스 | 2건 | 공식 명단의 회사명·별칭 대조 / 수주, 신용, PF, 실적, 안전 등 |

각 카드에 **큰 제목 → 1~2줄 간략 요약 → 출처·보도 시각**를 표시합니다.
뉴스 박스 전체를 클릭하면 해당 원문으로 연결됩니다. 별도의 원문 보기 버튼은 표시하지 않습니다.
시공사 카드는 대조된 시평 순위도 표시합니다. 캐피탈사 인수금융·투자 뉴스도 캐피탈업권 칸에 포함합니다.
개인 여신·소비자 보호 뉴스는 개인·리테일 칸에 우선 배정하며 캐피탈사 기사도 주제에 따라 이 칸에 포함합니다. 최대 6건을 한 페이지에 담습니다.
일반 은행 영업 홍보, 현대캐피탈 배구단 소식, 해외 Capital One·벤처캐피탈·도박 검색 결과는 제외합니다.
국내 캐피탈사의 경영 소식은 제외하지 않습니다. 예를 들어 `지배구조`의 `배구` 문자열은 스포츠로 판정하지 않습니다.
캐피탈사 판정은 코드의 국내 회사명/업권 표현과 금융·경영 키워드를 사용하므로 미등록 회사나 별칭은 누락될 수 있습니다.

요약은 공개 기사 본문에서 앞부분 핵심 문장을 짧게 **발췌**하거나, 언론사가 제공한 기사 설명문을 사용합니다.
새로운 사실·숫자·회사 영향을 추론하지 않습니다. 기사 본문 전체를 외부 AI에 전송하지 않으며 API 키도 필요하지 않습니다.
원문 접근 제한, 링크 해석 실패, 본문 식별 실패 때는 **요약 보류**라고 표시하고 상세 원인을 JSON에 남깁니다.
제목만으로 본문 내용을 만들어내거나 이전 요약을 재사용하지 않습니다. 긴 문장은 말줄임표로 줄일 수 있습니다.
원래 제공하던 규칙 기반 업무 검토 포인트는 JSON에 남기며, PDF에서는 뉴스 요약과 혼동하지 않도록 생략합니다.

## 실행

Python 3.12와 인터넷 접근이 필요합니다. 기존 체크아웃 `/workspace/first`를 사용합니다.

```bash
cd /workspace/first
bash scripts/install.sh
.venv/bin/python -m unittest discover -s tests -v
# 네트워크 없이 가상 기사·가상 시공사 순위·가상 요약으로 디자인 확인
.venv/bin/python -m cardletter --demo
# 실제 최근 24시간 공개정보 수집 및 원문 요약
.venv/bin/python -m cardletter
# 기간 확장 (1~168시간)
.venv/bin/python -m cardletter --hours 72
```

결과는 `output/cardletter-YYYY-MM-DD.pdf` 및 같은 이름의 JSON입니다.
가상 샘플은 `-sample` 접미사가 붙습니다. 날짜·보도 시각은 한국시간입니다.
JSON에는 기사 메타데이터, 요약, 원문 주소, 요약 근거 종류/실패 상태, 명단 출처와 수집 상태를 저장합니다.
기사 본문 전체는 저장하지 않습니다. 출력과 `.venv`는 Git에서 제외되며 같은 날짜에 재실행하면 그 날짜 결과를 갱신합니다.

한글 표시용 Nanum Gothic 글꼴을 PDF에 포함합니다. 출처는 Google Fonts `ofl/nanumgothic`,
라이선스는 `assets/fonts/OFL.txt` (SIL OFL 1.1)입니다.

## TOP100 명단과 발표 연도

TOP100은 **토목건축공사업 시공능력평가 순위**로 해석합니다.
`assets/contractors-top100.json`은 발표 연도, 공식 출처, 원본 파일과 SHA-256, 1~100위 회사명 및 별칭을 담습니다.
시공사는 해당 명단의 정확한 회사명/별칭과 대조합니다. 예를 들어 `한양대학교`를 `한양`으로 판정하지 않습니다.
회사를 5개씩 나눠 **명단의 100개사 전체**에 대한 공개 뉴스 검색을 수행하고, 상위 일부 회사만 검색하는 방식은 사용하지 않습니다.
별칭이 있으면 검색 수가 늘어납니다. 제목에 회사명이 없는 기사는 누락될 수 있고 검색 색인도 완전하지 않습니다.
기사 단위 중복 제거를 하며, 사건이 같은 서로 다른 제목을 모두 제거한다고 보장하지 않습니다.

**현재 명단은 대한건설협회의 2026년 정정 공시 원본(2026.8.1 적용)을 사용합니다.**
공식 원본의 토건 시트에서 1~100위 회사명·순위를 추출해 대조했습니다.
[공식 공시](https://www.cak.or.kr/lay1/bbs/S1T10C14/A/4/view.do?article_seq=159605)
원본 XLSX를 출처/체크섬 확인용으로 함께 보존하며, 뉴스 감시 명단에는 대표자·전화번호·등록번호를 넣지 않습니다.
기존 법인 표시(주식회사/㈜/(주))는 검색용 이름에서 제거하고 GS건설·DL이앤씨 등 통용 별칭을 함께 사용합니다.
현재 100개사와 별칭은 총 25개 검색 묶음으로 조회됩니다.
`--demo`의 샘플건설001~100 및 순위는 전부 가상이며 실제 수집에 사용할 수 없습니다.

매년 공식 공시가 갱신되면 새 XLSX의 토건 시트를 CSV로 추출한 뒤 원본과 대조해 가져옵니다.
추출은 `scripts/extract_rankings.py`를 사용하며 명칭이 같은 회사의 기존 별칭만 유지합니다.

```bash
.venv/bin/python scripts/extract_rankings.py \
  --xlsx /tmp/official-rankings-2026.xlsx --year 2026 --output /tmp/top100-public.csv
```

100개사 명칭·순위를 확인한 CSV를 아래처럼 가져올 수 있습니다.
`rank,name,aliases` 열을 사용하며 별칭은 `|`로 구분합니다. 원본에 대조한 명단에만 `--source-checked`를 지정합니다.

```bash
.venv/bin/python scripts/import_rankings.py \
  --csv /tmp/top100-public.csv \
  --source-file /tmp/official-rankings-2026.xlsx \
  --source-url 'https://www.molit.go.kr/공식자료주소' \
  --year 2026 --source-checked
```

위 원본 주소는 실제 공식 HTTPS 주소로 대체해야 합니다.
미완성/중복 순위, 모호한 회사 별칭, 다른 공종, 원본 체크섬 오류는 거부합니다.
기존 명단은 해시가 붙은 `.bak` 파일로 보존합니다. **원본 체크섬 검증은 파일 무결성 검증이며,
100개사 전사가 원본과 일치하는지는 자료 대조 과정에서 확인해야 합니다.**
PDF와 JSON에 사용한 연도·출처를 남기며, 매년 새 공식 자료가 발표되면 명단을 갱신해야 합니다.

## 공개 출처와 네트워크

- 금융위원회·금융감독원: 공식 보도자료 게시판 첫 페이지(현재 각 최신 10건)를 직접 읽습니다.
  기간 중 게시물이 많거나 기간을 늘리면 첫 페이지 밖 공지가 누락될 수 있습니다.
  날짜만 제공된 공지는 시각을 만들지 않고 기간에 걸친 한국시간 날짜로 선별합니다.
- 국토교통부: 공식 직접 게시판이 HTTP 503을 반환하여 Google News `site:` 검색과 출처 도메인 확인을 사용합니다.
  검색 결과 0건은 공식 새 공지가 없다는 뜻이 아닙니다.
- 뉴스: Google News 공개 RSS 검색. 본문 요약은 Google News 링크를 해석한 후 언론사 공개 원문에서 생성합니다.
  원문은 RSS 출처의 도메인 범위 안에서 HTTPS로만 읽습니다. 인증·유료벽·접근 제한을 우회하거나 TLS 검증을 끄지 않습니다.

필수 수집 대상은 `news.google.com`, `www.fsc.go.kr`, `www.fss.or.kr`이며,
공식 명단 확인에는 `www.molit.go.kr`, `www.cak.or.kr`, `www.kiscon.net` 접근이 필요합니다.
실제 선택 기사 요약에는 해당 언론사 도메인이 추가로 필요합니다.
현재 검증한 본문 대상은 `www.ynenews.kr`, `news.kbs.co.kr`, `www.businesspost.co.kr`,
`www.issuevalley.com`, `www.asiatoday.co.kr`입니다. 추가 기사 출처는 네트워크 정책에 따라 접근이 제한될 수 있습니다.
건설 전문 매체 `www.ikld.kr`도 설정 초안에 추가했습니다.
**초안 저장과 현재 실행 환경 적용은 다릅니다. 새 도메인은 환경 설정에서 저장·적용해야 합니다.**

현재 클라우드에서 RSS·공식기관 게시판·2026 TOP100 전체 검색과 실제 기사 원문 요약/PDF 생성을 검증했습니다.
초기 요청은 네트워크 정책 403으로 차단됐으나 도메인 설정을 저장한 이후 관련 출처 접속이 가능해졌습니다.
국토부 직접 게시판/PDF와 일부 사이트는 HTTP 503을 반환하므로 국토부 검색 누락 가능성은 남아 있습니다.
유료 기사, 본문 구조 변경, 출처 도메인 미허용 등에 대해서는 요약 보류 표시가 필요할 수 있습니다.
실제 뉴스의 제목과 본문 요약은 구분되며, 샘플 데이터를 실제 뉴스로 대체하지 않습니다.
수집 상태의 건수는 조회된 원시 목록/검색 결과 건수이고 카드 개수는 기간·관련성·중복 필터를 통과해 선정된 건수입니다.
일부 수집이 실패해도 확인한 기사만 PDF에 제공하며 실패 상태를 표시합니다.
전부 실패하면 수집 실패 안내 PDF를 만들고 종료 코드 2를 반환합니다.

## 매일 오전 8시 예약 생성과 메일

`.github/workflows/daily-cardletter.yml`은 매일 `23:00 UTC` (= 다음 날 한국시간 08:00)에
설치·테스트·PDF 생성을 실행하고 PDF/JSON을 GitHub Actions artifact로 7일 보관하도록 정의합니다.
메일은 발송하지 않습니다. 로컬 출력은 자동 삭제하지 않으므로 보관 정책은 별도로 정하세요.

파일만으로 예약이 활성화되지는 않습니다. 저장소 기본 브랜치에 커밋·푸시한 뒤 Actions를 활성화해야 합니다.
현재 저장소는 아직 커밋이 없는 상태이며 커밋·푸시·예약 활성화는 수행하지 않았습니다.
처음에는 수동 실행(`workflow_dispatch`)으로 PDF·명단·원문 요약 수집 상태를 확인하세요.
GitHub 예약은 지연될 수 있고 장기간 활동이 없는 공개 저장소의 예약은 비활성화될 수 있습니다.
정각 실행이 필요하면 회사가 승인한 상시 서버/스케줄러를 사용해야 합니다.
이 클라우드 세션의 프로세스가 다음 작업이나 게시 후 계속 실행된다고 가정하지 않습니다.

메일 서비스가 정해지면 승인된 SMTP/API, 배포 대상, 실패 알림과 중복 발송 방지를 별도로 연결합니다.
개인 수신자 목록·고객 정보·비밀번호를 저장소나 뉴스레터 입력에 넣지 않습니다.
현재 코드는 메일 주소나 자격 증명을 요구하지 않습니다.

개인·리테일 금융 원문 확인에는 `www.daejonilbo.com`도 사용합니다. 새 언론사 도메인이 허용되지 않았거나 본문을 읽을 수 없으면 해당 카드의 요약을 보류합니다.

## Python으로 직접 실행

PDF 상단 제목은 한국시간 카드레터 기준 날짜의 `YYYY/MM/DD/요일 Daily News`입니다.
ZIP 압축을 풀고 Python 3.12로 다음을 실행하세요.

```bash
python -m pip install -r requirements.txt
python run.py --demo
python run.py
```

`--demo`는 인터넷 없이 가상 기사로 확인하며, 인자 없이 실행하면 실제 최근 24시간을 수집합니다. 결과는 프로젝트의 `output` 폴더에 저장됩니다. Windows에서 python 명령을 찾지 못하면 `py -3.12`를 대신 사용하세요.
