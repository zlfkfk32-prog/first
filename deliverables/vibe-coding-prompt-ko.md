# 한국투자캐피탈 공개정보 카드레터 구현 프롬프트

당신은 Python 개발자입니다. 한국투자캐피탈의 업무 참고용 공개정보 카드레터를 구현하세요. 계획 설명으로 끝내지 말고 실행 가능한 전체 코드, 설치 방법, 테스트, 샘플 PDF를 만들어 주세요. 첨부한 기존 코드가 있으면 먼저 README와 구현을 확인하고 아래 요구사항을 유지하며 개선하세요.

## 목적과 범위
- 부동산 PF·부동산 금융을 최우선으로 하는 A4 한 장 한국어 PDF.
- 금융위원회, 금융감독원, 국토교통부의 공개 발표와 공개 언론 기사를 최근 24시간 기준으로 수집.
- 회사 내부 자료, 고객·직원·거래 개인정보를 입력하거나 수집하지 않음.
- 매일 오전 8시 Asia/Seoul 기준 생성 준비. 메일 서비스는 미정이므로 현재는 PDF 생성만 구현.

## 고정된 네 개 뉴스 칸
1. 부동산 PF·정책: 최대 2건. PF, 부동산 금융, 담보, 조달, 부동산 시장과 관련 정책·감독. 중요한 관련 공식 발표를 우선 고려.
2. 캐피탈업권: 최대 1건. 국내 캐피탈사의 실적, 연체, 건전성, 회사채·조달, 경영, 인수금융, 투자 동향. 한국투자캐피탈 직접 관련 뉴스 우선. 일반 은행 홍보나 해외 Capital One, 벤처캐피탈, 스포츠, 도박은 제외. '지배구조'를 '배구' 기사로 잘못 제외하지 말 것.
3. 개인·리테일 금융: 최대 1건. 개인·가계·신용·주담대·전세대출, 자동차금융, 리스, 할부금융, 금융소비자 보호. 캐피탈사 기사도 주제가 여기에 해당하면 이 칸에 우선 배정.
4. TOP100 시공사 주요 뉴스: 최대 2건. 해당 연도 공식 토목건축공사업 시공능력평가 1~100위 전사를 검색. 공식 명단과 회사명·별칭을 대조하고 순위를 표시. 수주, PF, 신용, 유동성, 실적, 안전·사고, 경영 등 주요 뉴스. 서로 다른 시공사의 뉴스를 우선 배치.

최대 6건. 칸에 맞는 기사가 없으면 '해당 기간 선정 뉴스 없음' 또는 검증·수집 실패 상태를 표시. 다른 분야의 기사로 빈 칸을 채우지 말 것. 같은 기사와 유사 제목의 중복 보도를 제거하고 미래 기사·기간 밖 기사를 제외. 게시 날짜만 있는 공식 발표는 한국시간의 조회 기간과 겹치는 날짜 기준으로 처리하고 시각 미제공을 표시.

## 제목과 요약
- 각 카드: 큰 제목, 바로 아래 1~2줄 간략 요약, 출처·게시 시각. 각 뉴스 박스 전체를 클릭하면 해당 원문 기사로 연결되도록 PDF 링크 영역을 지정. 오른쪽 아래 별도의 원문 보기 문구는 표시하지 않음.
- 요약은 공개 본문 핵심 문장의 짧은 발췌 또는 언론사가 제공한 설명문을 사용. 제목만 보고 사실이나 숫자, 회사 영향을 지어내지 않음.
- 본문 추출 실패, 로그인·유료 제한, 링크 해석 실패, 네트워크 차단이면 '요약 보류'를 표시. 이전 요약을 재사용하지 않음.
- 요약 방식과 실패 이유, 조회 상태, 공식 순위 출처를 별도 JSON에 저장.

## 순위 데이터
- 대한건설협회 등 공식 자료의 해당 연도 토목건축공사업 전국 순위 1~100위를 검증.
- 공식 원본 파일, 발표 연도, 출처 URL, SHA-256, 100개사 이름·별칭을 보관. 명단에 대표자·연락처 등의 필드는 복사하지 않음.
- 연간 자료 추출·검증·갱신 스크립트 제공. 명단 미검증·불완전·다른 업종이면 TOP100 여부를 추정하지 않음.
- 회사 이름 경계를 확인해 '한양'과 '한양대학교' 같은 오탐 방지.

## 구현과 디자인
- Python 3.12, ReportLab, BeautifulSoup, 공개 RSS·기관 게시판을 사용. API 키 없이 실행.
- 검증된 한글 글꼴을 PDF에 내장하고 라이선스를 포함.
- 네이비 헤더, 청록색 섹션 제목, 흰색 카드, 큰 제목과 작은 요약. 긴 제목·요약도 겹치거나 잘리지 않게 A4 한 장에 배치.
- URL 검증: 공개 HTTPS만 허용, 사설 주소·localhost·자격증명 포함 URL 차단, 출처 도메인과 리다이렉트 검사, 시간·응답 크기 제한.
- 실패를 숨기지 말고 수집 상태를 PDF에 표시. 전체 수집 실패는 실패 안내 PDF를 만들고 종료 코드 2.
- 실제 모드와 --demo 가상 샘플 모드 분리. 가상 기사·회사·순위·요약임을 명확히 표시.
- HTML/JPG 미리보기는 선택적으로 제공. 전달 시 개발 작업공간 링크만 쓰지 말고 이용 가능한 다운로드·첨부 방식으로 제공. 실제 PC 다운로드 여부는 별도로 확인.

## 자동화
- GitHub Actions의 매일 23:00 UTC cron으로 다음 날 08:00 KST 실행 준비. 수동 실행과 PDF/JSON artifact 저장 포함.
- Actions 예약은 정확한 정각 실행을 보장하지 않는다는 점을 설명.
- 기본 브랜치에 파일을 반영하고 Actions를 활성화하기 전에는 자동 실행이 활성화되었다고 말하지 말 것.
- 현재 메일을 보내지 않음. 추후 서비스가 정해지면 PDF 첨부 발송 모듈을 추가하고 발송 자격증명은 안전한 비밀 설정으로 관리. 비밀번호/API 키를 코드나 대화에 요청하지 않음.

## 완료 조건
- 모듈별 코드, 고정 버전 requirements.txt, README, 설치 스크립트, 순위 갱신 도구, GitHub Actions 파일 제공.
- 기사 기간·중복·분야 배정, 캐피탈/스포츠 오탐, 공식 순위 검증, 요약 실패, URL 보안, A4 한 페이지와 긴 텍스트 배치를 테스트.
- --demo와 실제 수집을 실행하고 가능한 범위에서 PDF 렌더링과 텍스트 추출을 확인. 접근하지 못한 출처와 남은 제한을 명시.
- 공개 정보만 사용하고 비공개 데이터·메일 수신자 목록·자격증명을 산출물에 포함하지 않음.

## 추가 확정 사항
- PDF 맨 위 큰 제목은 회사명 대신 한국시간 발행 기준 날짜로 `YYYY/MM/DD/요일 Daily News`를 표시. 한글 요일을 실제 날짜에서 계산. 과거 기사 PDF를 재생성할 때 날짜를 현재 날짜로 바꾸지 않음.
- `python run.py`로 실제 수집, `python run.py --demo`로 가상 샘플 생성. 최초 의존성 설치는 `python -m pip install -r requirements.txt`.

## 상세 브리핑 확장
PDF는 기존 A4 1페이지·6건을 유지하되 HTML은 별도 전체 최대 32건·분류별 최대 3건을 선정하세요. 8개 부문(PF·정책, 업권·캐피탈, 기업금융·IB, 개인·리테일, 투자, 리스크, IT·디지털, TOP100)을 제공합니다. 본문 기반 최대 480자·2문장 요약, 별도의 일반 업무 확인점, 쉬운 용어 사전, 부문 이동과 회사명·주제 검색, 출처·수집 상태를 포함하세요. 확인되지 않은 전일 증감·영향 분석·타임라인은 생성하지 마세요. 브라우저용 상세 HTML과 발송용 이메일 HTML의 호환성은 구분하세요.

## 홈 화면과 메뉴 배치
상단 메뉴를 가운데 정렬하세요. 홈에는 메인 이슈·부문별로 찾아보기·오늘의 핵심만 표시하고 홈 기사는 큰 제목·150자 이내 요약과 오른쪽 하단 원문 보기 링크로 간소화하세요. 상세 뉴스는 각 부문 메뉴나 타일을 클릭하면 해당 부문만 보여 주세요. 브라우저 뒤로/앞으로 이동과 직접 해시 링크를 지원하고 선택 메뉴를 표시하세요. 부문별 검색을 제공하며 수집 상태·전체 용어·기사 흐름은 수집 상태 탭에 모으세요. PDF의 박스 전체 원문 링크는 유지하세요.

## 최종 콘텐츠 변경
메뉴·양식·접속·실행 방법을 유지하고 모든 수집·선정을 부동산 사업장 중심으로 전환하세요. 시공사·PF·공사현장·지역별 개발·분양·입주·미분양·공정·조달·매각을 우선합니다. 시공사 부도·부실·하자·사고·회생 등 중대 이슈 보도는 홈 메인 최우선이며, 예방 캠페인을 발생 사고로 오인하지 마세요. 일반 금융권/리테일/IT 뉴스는 사업장 관련성이 있어야 합니다. 메뉴명은 유지하고 설명과 내용을 사업장 업무에 맞추세요. 확인되지 않은 위치·사업장명·공정·순위는 추정하지 마세요.
